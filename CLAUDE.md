# Millennium HR — notes for Claude Code

Internal HR web app for شركة الألفية للخدمات الضريبية والمحاسبية (Amman, Jordan). Arabic, RTL. The owner asks for changes in Arabic; answer in Arabic.

**New session? Read `docs/HANDOFF.md` first:** history of the original build conversation, live-system facts, the office fingerprint setup, and open threads with the owner. Tests: `tests/README.md`.

**Owner's standing request:** after every change, end the reply with the live link on its own line: https://hr.alabed-jo.com/ (the URL never changes; pushing to `main` updates it).

## Stack
- Static single-page app, no build step: `index.html` (all CSS + JS inline), `config.js`, `sw.js`, `manifest.webmanifest`, `icons/`.
- Hosted on GitHub Pages from `main` (root) at the company's own domain: https://hr.alabed-jo.com/ (`CNAME` file; DNS at GoDaddy: CNAME `hr` → `barhoom98.github.io`). The old https://barhoom98.github.io/idarat-al-mawarid-al-bashariya/ redirects there. Pushing to `main` deploys. Every path in the app is relative, so it works at either address.
- Backend: Supabase project `millennium-hr` (ref `nxhlxwpwpyicyprnsdfp`, eu-central-1). Client: supabase-js 2.49.4 UMD from jsDelivr (fallbacks in `index.html`).
- After changing `index.html` or other shell files, bump `CACHE` in `sw.js` and `APP_VERSION` in `index.html` (shown in the side rail, so the owner can confirm they have the latest). The open app checks for a new service worker every 15 minutes and when its window comes back, and reloads itself once the new one takes over (after any open dialog or unsaved settings). An app installed from the old github.io address cannot update (that address only redirects, and a service worker script behind a redirect is refused): it must be removed and installed again from https://hr.alabed-jo.com/.
- Choosing a client anywhere uses `clientPicker()` (searchable box: name, tax number or accountant; Arabic letters normalised by `normAr`) — use it for any new client field instead of a plain `<select>`.
- Phone layout (≤ 860px, `isPhone()`): a fixed icon tab bar (`#tabbar`: الرئيسية، الحضور، mic، المهام، المزيد) replaces the rail's links; every page's table becomes cards built with `rec()` / `stats()` / `sect()` (the `…P` functions: `homeP`, `attDayP`, `clientsP` …), dialogs are bottom sheets, and nothing may scroll sideways (`tests/smoke.js` fails if a page does or shows a `.tbl-wrap`). Each `render…` function computes once, then returns its phone variant; keep both in step when a page changes. Cards the person opened are remembered in `UI.openK`. With 570+ clients, a folded client group (`sect(…, {lazy})`) draws nothing until opened, then `CLIENT_STEP` (60) cards at a time («عرض … أخرى»).
- Voice tasks: the mic opens the task form and starts the browser's speech recognition (`ar-JO`, falling back to `ar-SA`, `ar`; where there is none, the box says to use the keyboard's microphone). `parseTaskSpeech()` in the pure block turns the sentence into title, employee, client, date, time, years, priority, category and repetition; `voiceApply()` fills the form, never overwriting a field the person edited (`data-touched`). Greetings and courtesies (`VOICE_GREET`: صباح الخير، يعطيك العافية، لو سمحت …) are dropped first: the manager opens with them, and «صباح الخير» once picked «شركة تل الخير». A client is picked on its rarer name words, most of all a stretch said in the name's own order; a single word alone needs a cue (شركة، مؤسسة، ملف، ل…) or a name hardly anyone shares, else it is only offered. «يا شادي» or a first name right after the greeting names the employee. The owner's rule (23 Nov): a client said clearly is picked with nothing offered beside it (a whole name said exactly, or «شركة …» before a company's name, settles it); only look-alike names are offered as chips (as close as the best, or carrying every distinctive word it matched, e.g. a family name alone), never names sharing one word. Check changes against the real client list in a scratch script, never in the repo.
- WhatsApp notice: `waSheet(taskId)` shows the message (`taskMsg`) and a `https://wa.me/<number>?text=…` link to the employee in charge (`employees.data.phone`, normalised by `waNumber`); the manager presses send inside WhatsApp. Pressing the link stamps `tasks.data.wa_at`. Nothing is sent by a server: automatic sending would need the WhatsApp Business API.
- Task reminders (owner's request, 23 Nov: «تنبيه للمهمة قبل موعد الإنجاز بيوم يوصل على التلفون»), two parts:
  - Manager: a Web Push notification the day before a task is due. Settings → «تذكير المهام» (first card), or the yellow bar `pushBanner()` on the home and tasks pages (one-tap «تفعيل»; «كيف؟» opens `pushHelp()` for an iPhone in Safari or blocked notifications; «لاحقاً» hides it on that device), turns it on per device (`pushOn`: permission, VAPID key from the function, `pushManager.subscribe`, row in `push_subs`; `pushCheck` on every start re-saves the subscription). pg_cron job `task-reminders` (`5 5-18 * * *` UTC = 08:05–21:05 Amman) calls edge function `task-reminders` (`{mode:'run'}`, header `x-cron-key` from `private.push_config`); from `settings.remind_hour` (default 9) it sends one notification for every open task due tomorrow (plus tasks due today that were added after the last run the evening before), then stamps `tasks.data.reminded = due`. Nothing is stamped while no device is on. The notification uses the phone's own sound; `sw.js` shows it and opens `#tasks`. iPhone: only from the home-screen app, iOS 16.4+. The VAPID private key is made inside the function on first use and lives in `private.push_config` (service-role RPC `push_config()`); never put it in the repo.
  - Employee: the WhatsApp message carries a link to `cal.html?k=<task id>&t=<tasks.data.cal_token>` (token made by `waSheet` on the first notice). `cal.html` reads edge function `task-cal` (`f=json`) and offers `f=ics` (calendar file, alarm the day before: `-P1D` for a timed task, 9:00 the day before for an all-day one) and a Google Calendar link. `taskForm` keeps `cal_token` and clears `reminded` when the date changes; `spawnNext` clears both.
- Printing: the leave form and payslips are built by `letterDoc()` (one `.lvdoc`, one `.sheet` per A4 page, letterhead unless «ورق مروّس جاهز») and shown in a preview dialog; «طباعة» prints only `#print-root`, «حفظ PDF / مشاركة» uses html2pdf.js (cdnjs), one canvas per sheet, and the share sheet on phones. `rtlCanvasText()` makes html2canvas draw Arabic right-to-left while a PDF renders (without it, words run together and «:» «(» jump).
- Payslip («كشف صرف راتب», owner's layout of 25 Nov): no working/attendance days row; the net is shown in figures «… دينار أردني» and in words «فقط … لا غير» from `amountWordsJOD()` in the pure block (dinars and fils, Arabic number agreement; tested in `tests/calc.test.js`).
- Board membership («كشف صرف عضوية مجلس إدارة», 25 Nov): a separate monthly statement for anyone with `employees.data.board = {amount, tax}` (set in the employee form; the general manager has one). No attendance, overtime, SSC or hourly wage. Shown under the payroll table (`boardCard`), edited per month in `boardForm` (`payroll[ym].board[empId]`), printed by `boardDoc` (same look as payslips, `SLIP_CSS`); approving a month snapshots `board_rows`. Amounts live only in Supabase.

## Data model (Supabase, schema public)
- Document tables `(id text pk, data jsonb, updated_at)`: `settings` (row `main`), `employees`, `leaves`, `clients`, `tasks`, `payroll` (id = `YYYY-MM`; `locked`, `rows` snapshot, `adj` per employee, `board` per board member, `board_rows` snapshot).
- `clients.data`: `name, tax_no, kind` (company|est|person|ngo)`, employee_id` (the sales-tax accountant; empty for income-tax-only files)`, gst_cycle` (even|odd; empty = not registered for sales tax)`, sales_tax, income_tax, directorate, doc_status, contact, phone, email, fee, notes, source, created`. Ids are `cl-<taxno>`. Sales-tax clients stay grouped by their accountant; the owner says when a new one joins and who handles it. The 454 income-tax files from «كشف تسليم كشوف التقدير الذاتي 2025» (`source` «ملف ضريبة الدخل 2025») carry only name, tax number and kind, by the owner's choice.
- `tasks.data`: `title, client_id, employee_id, category, due, time` (HH:MM, optional)`, years` (text, «2023، 2024»)`, priority` (normal|high|urgent)`, status` (new|progress|waiting|done)`, recur, notes, created, done_at, wa_at`.
  Reminders add `reminded` (the due date last reminded) and `cal_token` (the employee's calendar link).
- `push_subs (endpoint pk, data jsonb = PushSubscription.toJSON(), device, email, created_at, last_ok, last_error)`: devices that get task reminders (admins via RLS). `private.push_config` (one row: VAPID pair, `cron_key`) is reachable only through service-role RPCs `push_config()`, `push_config_set_vapid()`, `task_mark_reminded()` (migration `20261123000000_task_reminders.sql`).
- `attendance_days (date pk, data jsonb)`: manual corrections only — `data.rec[employeeId] = {in, out, mark: 'field'|'' , note}`.
- `punches (fp_id, punched_at timestamp local Amman time, source import|device|manual, unique(fp_id, punched_at))`: raw fingerprint events. Employees map via `employees.data.fp_id`.
- `bridge (id 'main', key, last_seen, device)`: office bridge key + heartbeat.
- `app_admins (email)`: who may use the app. RLS on every table: `private.is_admin()` (JWT email in app_admins).
- Realtime publication includes all of the above; the app subscribes to `postgres_changes` on schema public.

## Adding a user
Sign-in is by **username** (the owner's is `ALABED`). The app maps a username to the internal address `<username lowercase>@users.millennium-hr.invalid` (`USER_DOMAIN`, `loginEmail()`, `userLabel()` in `index.html`); anything typed with `@` is used as a real email. `.invalid` is a reserved domain, so nothing is ever mailed there — password resets by email don't apply; change passwords in the app (الإعدادات → حسابي) or in the Supabase dashboard.
1. Create the auth user with email `<username>@users.millennium-hr.invalid` (Supabase dashboard → Authentication → Add user, with "Auto confirm"), or SQL insert into `auth.users` + `auth.identities` with empty-string token columns.
2. `insert into public.app_admins (email) values ('<username>@users.millennium-hr.invalid');`
3. To rename an existing user, update `auth.users.email`, `auth.identities.identity_data->email` and `app_admins.email` together (the app refreshes the session once if the admin check fails).

## Fingerprint
- Edge function `punch-ingest` (`supabase/functions/punch-ingest`, verify_jwt=false): checks header `x-bridge-key` against `bridge.key`, upserts punches, updates heartbeat.
- `bridge/millennium_bridge.py`: Windows office PC, pyzk (ZKTeco, port 4370). One long live_capture connection all day; `quiet()` skips pyzk's CMD_CANCELCAPTURE/CMD_STARTVERIFY (they reset the reader and make the device beep), so even reconnects should be silent. TCP keep-alive detects a dead device; failed connects back off 30 s → 10 min. Punches queue in `state.json` (`pending`) when the internet is down, so internet trouble never reconnects the device. Full re-sync on start, after errors, and once a night at 03:00. Heartbeat every 5 min carries `status` (version, connects_today, last_error) → `public.bridge.status`: check it first when the owner reports beeps or missing punches. Read-only: never send the device write/clear commands.
- Files can also be imported in the app (attlog.dat / TXT / CSV / Excel).

## Calculation rules (in the `/*PURE-START*/` block of index.html)
- Work schedule per weekday in settings (JS getUTCDay: 0=Sun … 6=Sat). Default Sat–Wed 08:30–17:30, Thu 08:30–14:30, Fri off.
- Late = minutes after start when beyond `grace` (15). Overtime = minutes after end ≥ `ot_min`, paid at `ot_rate` 1.25; any work on an off day/holiday paid at `ot_rate_off` 1.5 (Jordan Labour Law art. 59).
- Hourly wage = basic ÷ `day_divisor` (30) ÷ `hour_divisor` (8). SSC 7.5% employee / 14.25% employer on (basic + allowances) capped at `ssc_cap`.
- Days before `settings.start_date` or an employee's `hire_date` are not evaluated.
- Missing punch (`fill_missing`, on by default; الإعدادات → التأخير والوقت الإضافي): on a working day that is over, punches before the middle of the schedule are arrivals and after it departures, and a side with none takes the scheduled start or end (8:30 / 17:30, Thursday 14:30). `res.filled` ('in'|'out') marks it: shown dashed with «بصمة مكمّلة», noted in the Excel report. Real punches and manual corrections are kept; a day with no punch at all is still an absence. The owner asked for this on 14 Nov: staff go to clients and don't come back to punch.
- An employee's `fp_id` may list several device numbers (`"11, 1"`, parsed by `fpIds`). Presses within `punch_gap` (10) minutes collapse into one punch (`collapsePunches`).
- Standing field work: `employee.field_from`…`field_to` (empty `field_to` = open-ended) makes every *working* day in the period status `field` (no late/absence; Fridays/holidays stay off; leave still wins). A day's own `mark` overrides it: `field` forces field work, `office` means go by the fingerprint.
- Money is JOD with 3 decimals (fils).
